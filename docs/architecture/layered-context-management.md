# 分层上下文管理补充设计

日期：2026-09-29。来源：用户提供的四张 Snip / Collapse / AutoCompact / 文件上下文恢复截图。这里采用其中的设计思路，不将截图中的实现名称、百分比、固定 Token 数值或子代理行为认定为已经核实的 Claude Code 官方实现。Pi 的源码核对仍以 pi-session-source-review.md 为准。

本文扩展既定完整计划，不删除树形会话、结构化摘要、来源校验、长历史分块合并、长期记忆、Git 恢复、身份与项目权限等功能。当前代码已有压缩节点和上下文投影，缺少完整预算策略与自动调度；不是只有条件判断，也还没有实现本文全部机制。

## 预算与调度

每次执行模型请求前，预算整个请求：当前系统规则、任务约束、工具 schema、授权记忆、摘要、原文、文件恢复内容、协议开销，并预留输出与安全余量。供应商有独立输入/输出限制时分别检查。usage 按供应商语义归一化，缓存计数不重复相加；分支、投影、模型或规则变化后使旧 usage 基线失效。

示例初始配置采用可用输入预算 B 的比例，而不是模型标称总窗口：Snip 70%、Collapse 准备 80%、AutoCompact 90%、压力阻断 95%，最终请求必须满足硬预算。比例可配置且不是质量保证。reserve_tokens、输出上限和安全余量必须先从总窗口约束中扣除。轻量操作可在工具返回后预处理，但每次请求前仍复查。

统一 ContextController 是上下文变更的调度者，同一会话最多一个摘要任务在准备/提交；不能让 Collapse 与 AutoCompact 同时写入互相覆盖。低压时直接请求；中压先 Snip，仍超阈值再 Collapse；Collapse 无效、失败或来不及则转 AutoCompact。已有有效候选可复用，不无条件全局禁用兜底。应用变更后重新计数，足够后立即停止，不固定把三层全部执行一遍。使用最小收益、冷却期和滞回避免反复压缩。

达到阻断阈值时暂停新的模型请求和扩张性任务，包括未来的子任务派发；允许正在完成的工具结果落盘、取消、对账和压缩，不能因此留下悬空 tool_call。当前单 Agent 阶段不为模仿截图额外引入子 Agent。

## Snip：自动缩减旧工具输出

不调用模型。只替换模型投影中的旧工具结果正文，保留消息、调用关联 ID、错误状态、退出码及关键定位信息。完整输出必须在截断前写入产物存储，使用服务器生成的 artifact_id、内容哈希、来源消息/工具运行 ID、项目作用域。不能先按现有 run_python 的 12000 字符限制丢弃原文，再宣称可恢复。

候选来自已完成的较早工具交互组；按上下文压力、输出大小、组年龄与重复读取情况选择。优先大型重复 read/search/命令输出，保护最近完整组、未解决错误的必要证据、待确认副作用与未知执行状态。显式保护原因和 Token 预算，不只凭模型认为“没用”。状态保护应提取精简证据，避免全部错误日志无限常驻。

投影示例：保留 role/tool_call_id/is_error/exit_code，将 content 替换为状态、短预览、artifact_id、版本与按范围读回说明。按需读回也有预算，避免立刻把全文重新塞满上下文。工具调用配对不变，不删除整条结果。无状态命令的幂等性不能从输出清理推断。

持久化为独立的 Snip 控制记录（规划名 SnipApplied），引用分支锚点、目标节点及内容哈希，不更改旧节点；只在祖先范围满足条件的分支生效。相同内容重复 Snip 无额外记录。原始工具响应和来源文件的当前内容不同：前者读产物，后者重新读取文件，必须标记时间/版本。

## Collapse：局部片段折叠（前缀压缩全流程完成后实现）

当前 CompactionEntry 表达旧前缀摘要，不足以表达任意中段替换。新增独立 CollapseEntry 设计：id/session_id/parent_id、source_start_id/source_end_id、source_leaf_id、source_view_revision、source_digest、summary、来源集合、状态/模型/usage 等。一个连续稳定范围折叠为一份局部摘要；范围两端对齐完整交互组，不跨分支、不覆盖尚未结束的工具组，不吞掉必须独立保留的原始约束。

示例：A B C D E F -> A B [C-D 的摘要] E F。原文仍在 JSONL；只有模型投影替换。首个实现只接受不重叠区间，不做任意嵌套；后续全局压缩可以吸收局部摘要。该限制是实施顺序，不删除后续扩展能力。

先实现同步生成/提交，再增加异步准备。后台摘要工作器只可读快照并调用摘要模型，不执行业务工具。任务仍可追加 E/F，但提交必须在下一次模型请求前的同步边界完成。

提交时检查：锚点仍是当前分支祖先、来源连续且哈希未变、投影视图修订未发生冲突、无重叠折叠/全局压缩、摘要结构与引用有效、预计节省足够；在单写者锁内追加记录。尾部追加可以在验证通过后重基提交，source_leaf_id 仅作为准备时快照，不能假装它一直等于当前叶子。分支切换、全局压缩或来源失效则取消/丢弃候选。不能把现有全局压缩节点的严格父节点校验直接放宽来实现异步局部折叠。

## AutoCompact：兜底前缀压缩

复用现有 CompactionEntry / ContextSummary / ContextSummarizer，但由统一预算策略调度。

路径一为可复用的会话摘要快照：后台/轮次边界已生成的 SessionSnapshot 必须绑定 session、分支祖先、覆盖边界、投影版本、摘要 schema、来源与模型信息。命中时直接构建快照 + 未覆盖的近期完整原文，不额外调用摘要模型；生成快照本身仍有成本。过期、跨分支、约束版本不符或预算收益不足的快照不能使用。SessionSnapshot 是会话内短期材料，不是跨会话长期记忆，也不能直接拿任意 memory 文件覆盖历史。

路径二为新的模型摘要：上一份摘要 + 新待压缩有效历史，按摘要输入预算分块、总结和合并；长轮次单独保留其前缀任务状态。不能把已经超窗口的整段历史原样发送，也不能通过直接删除最旧消息抹掉目标/限制。合并信息保留来源、冲突和证据版本；全部成功后一次发布全局节点，生成失败不发布半成品。

全局压缩基于有效投影工作，吸收覆盖范围内的局部摘要和旧全局摘要；对未覆盖的原文保留 Snip 效果。持久化覆盖集合/视图修订以避免重放时恢复已被摘要替代的原文或重复注入局部摘要。出处校验保留原始引用集合，可按需读回产物。

## 压缩后重新构建文件与任务上下文

ContextBuilder 先注入可信项目规则、当前身份授权得出的能力约束、独立的原始任务限制和有证据的任务状态；摘要不能成为权限来源。摘要中的历史限制与当前可信规则冲突时不能越权执行。

FileContextIndex 跟踪工具实际读取/修改结果、规范路径、哈希、时间与相关任务。任意命令可能操作未知文件，不能只看命令字符串就宣称掌握所有读写。已知修改可结合后续文件检查/Git diff，对未知范围如实标记。

压缩成功后按当前任务相关性和最近访问选择少量文件/片段，重新授权并从磁盘读取，记录最新哈希。排除密钥、二进制、超大文件和由规则加载器/任务计划模块另行注入的内容。示例上限为最多 5 个文件、单文件 2K、总计 8K Token，仍必须服从当前剩余预算；这些数值仅为可配置初始值。文件删除、变化或无权限时记录状态，不回放旧缓存冒充当前文件。

文件恢复之后再次计算完整请求预算。预算不足则减少可选文件片段，不移除强制约束。任务与文件恢复不重新运行历史命令；旧测试通过不证明当前新哈希代码已通过。

## 失败处理与验收

摘要工作设总调用、总 Token、超时和取消预算。格式/来源错误最多一次纠正；认证错误不重试；摘要输入超限切分或缩减非关键预览，不原样重试；瞬时网络错误单独配置有限重试。预算控制总体次数，不能让分块、格式和网络重试乘法膨胀。

连续 3 次完整压缩作业失败可打开自动摘要熔断，保留只读诊断、产物访问和手动恢复入口；不关闭本地 Snip。熔断后若仍超硬预算则保存进度并停止，不能照常发送超限请求。计数单位是完整作业而非每个分块调用，成功重置；冷却/配置变化后的恢复需明确策略。

执行模型发生明确 context overflow 时，重建上下文后最多重试该模型请求一次，不重放已执行工具；这与摘要模型自身重试分开。超过上限返回明确状态。

必须验收：Snip 零摘要请求、调用配对不变、完整原文可按权限读回、重复应用不增长；局部折叠只替换指定范围、异步尾部追加可验证提交、切分支丢弃候选；快照命中无新摘要请求、快照过期回退；全局压缩吸收旧摘要不重复、不复活 Snip 正文；文件恢复重新读取且权限/总预算生效；压缩失败不发布、熔断可观测、超限重试不重复工具副作用。

## 教学实施顺序

1. 验证已有 ContextSummarizer，连接生成—校验—提交的基础压缩流程。
2. 完整请求预算、任务约束独立保留、工具完整输出产物化。
3. 自动 Snip 与产物按范围读回。
4. 会话摘要快照复用、完整前缀 AutoCompact、长轮次/分块合并、压缩后文件恢复。
5. 前缀流程统一控制器联调、冲突取消、熔断与请求级溢出恢复；验收任务可继续、约束保留、工具不重放及预算合规。
6. 完成上述全流程后，实现同步 Collapse 与不重叠范围投影，再做异步准备/同步提交并接入统一调度。

第 6 步的同步 Collapse 与后台准备/请求前提交已实现并接入 CLI。80% 压力下启动后台生成，主流程继续；后续请求前提交已完成且有效的候选。90% 或强制压缩直接进入前缀流程，不等待后台候选。后台不写会话，来源与收益在主线程发布前重新检查。阈值均按输入预算计算。

实现中保持单写者；现有无锁文件追加不视为已完成并发控制。以上阶段均纳入最终功能范围，不要求 benchmark 对比，只做功能与故障验收。
