# 会话、上下文与记忆设计补充

来源：用户提供的 11 张 Sessions / Compaction 讲解截图。以下是 ForgePilot 采用的设计，不是对截图所述 Pi 当前源码行为的逐项确认；实现课程开始时需核对对应仓库版本、代码和测试。

## 三类状态

- 会话：保存发生过的消息、工具执行与控制事件，能重建分支及执行进度。
- 模型上下文：从当前分支构建本次请求内容，可包含摘要、近期原文、项目规则和授权记忆，不等于完整日志。
- 长期记忆：跨任务可复用的项目知识，经过来源、版本、验证与权限处理；不把所有历史或压缩摘要自动入库。

## 存储与职责

采用每个会话一个追加式 JSONL 事件文件，首行为带 schema_version、session_id、project_id、owner_id、cwd、可选 parent_session_id 的元数据。文件放服务管理的数据目录，使用可信 ID 定位，不接受客户端直接指定会话文件路径。按项目分目录只是组织方式，不是授权机制。

SQLite 继续管理用户、项目、任务及查询索引；会话历史以 JSONL 为事实来源，索引可重建，避免两套独立历史相互冲突。相比旧方案，改变的是会话日志的存储介质，全部功能保留。

消息/摘要等树节点包含 id、parent_id、type、payload、时间与序号。当前分支通过 active_leaf_id 表达，切换时追加独立的 cursor_changed 控制事件（带目标节点 ID），重放后恢复游标；控制事件不能被当作用户消息或意外插入语义父链。

单会话单写者/写锁，父节点必须已存在且属于本会话，节点 ID 唯一。消息完成即写入，工具开始/结束另有执行事件；不能等整轮成功才落盘。流式片段不必逐 token 写入。配置修改在轮次边界生效并记录，执行中使用固定配置快照。

append 不自动等于断电安全：明确 flush/fsync 策略；恢复时识别末尾未完整写入记录，不能静默跳过中间损坏。会话日志不等于副作用 exactly-once；未确认完成的工具运行需对账。

## 分支与模型上下文

正常消息指向当前叶子；返回历史节点后新消息形成分支，旧分支不删除。

例：A→B→C→D，回到 B 后追加 E，当前分支为 A→B→E。

get_path_to_root(leaf_id) 沿 parent_id 回溯并反转，返回根到当前节点的有序路径。build_session_context(path) 再处理摘要边界和消息格式。原始分支遍历与模型请求构建是两个独立步骤，不能直接发送所有 JSONL 行。

工具调用组只在完整交互边界分叉/裁剪；中断造成的待完成工具记录按明确策略补全或标记取消，不伪造成功。用户身份和权限由运行时重新检查，不从历史记录直接恢复授权。

## 压缩节点

压缩成功后追加 compaction 节点，不覆盖旧消息。字段包含 summary、first_kept_entry_id、source_leaf_id、摘要版本和计数信息；保留起点必须在来源分支中，且不切断调用与结果组。

例：A→B→C→D→K→E，K 为压缩节点、parent_id=D、first_kept_entry_id=C，摘要替代 A/B 的可压缩历史。模型上下文为摘要+C+D+E；系统规则、原始约束和可信运行信息由上下文构建器按策略保留/注入。原文仍在日志里。

仅使用当前分支路径上的适用压缩节点，不能使用整个会话最后生成的摘要。连续压缩要定义新摘要覆盖先前摘要与旧消息的关系，避免重复拼接或遗漏。失败/取消不发布半成品摘要，保留原历史。

策略与机制分离：ContextPolicy 决定触发和保留量，Compactor 生成并校验摘要，SessionStore 记录，ContextBuilder 构建请求；Harness 调度这些组件。

轮次结束、下轮开始允许提前压缩；每次模型请求前仍要预算检查，防止单轮工具循环膨胀。窗口溢出只有限重试失败的模型请求，不重放已执行工具。摘要本身需要模型输入/输出预算，已经太大时需分块或减少摘要输入。

usage 按供应商字段语义归一化，缓存计数可能已包含在输入计数中，不能盲目相加。记录 usage 对应的上下文边界及模型；新增尾部消息估算，压缩/分支/模型变化后使旧统计失效。输出预算、工具定义、系统规则也计入请求预算。

截图中的 reserveTokens=16384、keepRecentTokens=20000 不作为硬编码标准；参数按模型窗口和任务配置。字符数除以 4 只能粗略估算，尤其不能当作中文内容的精确 Token 数。

摘要模板：Goal；Constraints & Preferences；Progress（Done/In Progress/Blocked）；Key Decisions；Next Steps；Critical Context。保留精确路径、函数名、错误、测试命令及对应代码版本；区分事实与猜测，引用原始事件/产物。历史作为待总结数据，摘要调用不执行历史里的工具请求或指令。

## 分层预算策略与任务检查点（新增截图补充）

### 分块总结与合并（后续截图确认）

先按完整交互组划分近期保留区与旧历史压缩区；小历史直接总结，长历史按摘要请求预算分块，块数不固定为两块，近期保留量不固定为 20000 tokens。各块使用统一摘要结构和来源引用；合并时去重、按时间和代码版本更新事实，保留未解决的冲突。合并输入仍过大则分层合并，设置总调用/Token 预算。摘要请求的可重试错误与原执行模型的上下文超限重试分开计数；认证错误不重试，摘要输入超限需缩块。所有块及合并结果校验成功后才发布压缩节点，失败不发布缺块摘要。增加块边界不拆工具组、版本证据不混淆、部分失败不发布的验收。

新增材料是参考设计，不是本项目已完成的功能，也不据此断言 DSH 当前实现。采用以下策略，并在对应课程验收。

- 每次模型请求前计算完整请求预算。将 80% 触发、16% 近期历史作为可配置的初始策略值；以归一化后的可用输入预算为基准，不机械套用供应商标称总窗口。必须预留输出、协议开销与摘要生成空间，系统规则、工具 schema、任务状态和记忆也计入输入。
- 分层处理输出：小结果保留原文；中等结果提供错误附近等关键片段并保留原始记录；超大结果存到产物文件，只向模型提供预览、元数据与可授权读取的引用。落盘发生在原文被丢弃之前，摘要/裁剪只改变模型视图。现有 grep 的先截断后返回属于教学版本，未来必须在执行层捕获完整输出后再生成预览。
- 若输出预算处理后仍达到触发阈值，压缩较早历史；近期保留量按完整交互组调整，而非机械截取 Token。多工具调用时保留整组调用及各自结果，进行中的调用不切断。
- 任务状态独立于自然语言摘要，记录 task_id、目标/约束、阶段、待办、base_commit、patch/content hash、验证结果关联版本、待完成 tool_call_id、job_id 和最后确认状态。该状态由程序和执行证据维护，不把模型推测当成事实。
- 压缩前保存一致的任务检查点，压缩后 ContextBuilder 注入当前结构化状态与历史摘要。例如等待回归测试时，应查询已登记 job_id，而非重新提交同一测试。测试通过只适用于其关联代码版本；代码变更后旧结果保留为历史，不能标记新版本已通过。
- job_id 必须能对应可查询的执行后端及实际作业状态，单独保存 PID/字符串不足以保证进程恢复。状态未知时进入 interrupted/needs_input，不凭摘要断言作业成功，也不盲目重复有副作用的操作。
- 仅对明确的上下文超限执行“外存/裁剪→摘要→重建请求→重试一次”。重试的是失败的模型请求，不回放工具循环。若仍超限或压缩失败，保存进度、返回明确停止原因；API 密钥错误等不能触发压缩重试。摘要请求自身放不下时需分块或缩减输入，不能原样发送同一超大历史。

新增验收：触发两级处理与跳过无需压缩的请求；原文可按授权读回；压缩后等待中的作业仍对应原 job_id；旧测试不会证明新补丁；超限最多重试一次且工具副作用次数不增加。

## Git 与长期记忆

切换对话分支不会自动回退代码。代码恢复是独立检查点操作，关联节点、基准 commit、工作区/索引状态及必要未跟踪文件。

不直接照搬 stash create/apply 等同完整快照恢复的说法：create 不自动包含未跟踪文件，返回对象也需保活；apply 是应用变更，可能冲突或保留额外修改，不等于精确还原。恢复前核对当前状态并保护用户修改。

长期记忆保留既定候选→验证/确认→入库→授权召回→更新/失效流程，与会话摘要分别存储管理。会话、摘要、代码产物和记忆都遵守当前项目访问权限。

## 短期与长期记忆的具体契约（新增截图）

短期记忆服务于当前任务继续执行，由结构化任务状态、当前分支近期原文、早期历史摘要组成；包含目标/约束/验收条件、阶段、工具结果与错误引用、代码版本与补丁、已确认事实、待验证假设、待办、待完成作业与审批状态。完整原始历史保留在会话存储中，而非全部放入模型上下文。恢复待审批状态不等于自动恢复执行许可，实际权限仍重新校验。

长期记忆只提炼可跨任务复用的信息，分为四类：

1. 项目约束与工程决策背景：兼容性要求、验证命令、设计取舍及来源。
2. 已验证修复案例：问题现象、根因、修复思路、对应补丁与验证证据。
3. 有证据的失败经验：尝试方案、失败现象、环境和适用条件；不得把某次失败泛化为永远不可行。
4. 用户明确表达的协作偏好：例如先讨论方案再修改；标注用户/项目范围，不从单次行为随意推断。

建议 MemoryRecord 字段：id、kind、content、project_id、owner_id/visibility、source_session_id、source_entry_ids、artifact_refs、base_commit/适用版本范围、verification_status、evidence_refs、created_at、updated_at、supersedes_id 与失效原因。按记忆类型区分验证证据：偏好引用用户原话，修复案例引用测试与代码版本，项目约束引用规则或确认记录，而非所有记忆都依赖测试通过。

生命周期为候选→验证/用户确认→启用→更新/替代/失效。冲突信息保留来源并明确哪条有效，不能默默覆盖成无来源结论。工具执行成功不自动证明任务或根因正确；未验证模型猜测不得按事实入库，可留在短期待办中。

禁止把密钥、凭据及一次性审批授权写成可复用记忆。用户偏好不能覆盖项目权限或审批策略；审批绑定任务、动作和有效范围。长期记忆只能参与上下文建议，不能授予执行权限。

召回先做身份和项目范围过滤，再按相关性、适用版本、验证状态和时效选择，最后按独立 Token 预算注入。失去项目权限后，会话、产物、摘要与记忆同步受限。第一版仍使用 SQLite 和简单文本检索；不以引入向量数据库作为完成记忆功能的前提。

验收补充：四类记忆各有一条可追溯示例；猜测不进入有效事实；失败经验保留条件；偏好不得替代授权；版本变更可使旧经验失效；来源撤权后不可召回；跨会话复用不会携带原任务的一次性审批。

## Claude Code 补充机制

已核对的官方行为与 ForgePilot 取舍详见 [Claude Code 参考记录](../references/claude-code-reference.md)。采用以下补充契约：

- 项目规则与自动提炼记忆分开管理；RuleLoader 只加载授权范围内的通用规则和当前访问路径适用的目录规则，记录来源与内容版本。规则提供指导，不能授予权限。
- ContextBuilder 在压缩后重新装配适用规则，不仅依靠摘要保留。手动压缩与自动压缩共用预算检查和完整交互边界，用户重点不能覆盖强制保留项。
- 长期记忆提供有预算的授权索引，详情按需取用并再次授权；SQLite 是事实来源，不另建独立 Markdown 历史。索引、详情、缓存都遵循当前权限和失效状态。
- 提供候选生成开关及记忆查看、来源、修正、停用/删除能力；关闭自动候选生成与禁止已有记忆召回是两个不同设置，不混淆。
- 提供上下文组成和加载来源报告，分别标注估算 Token 与实际 usage，便于解释压缩原因及排查规则遗漏。

## 验收与课程顺序（汇总）

1. 追加、重启重放、坏尾行识别、并发写入控制。
2. A-B-C-D 与 A-B-E 分叉、切换、重启后恢复游标，不串分支。
3. K 摘要+保留起点构建、连续压缩、回到旧分支、工具配对不丢失。
4. usage 边界、长工具输出、压缩失败、单轮增长与溢出恢复。
5. 会话恢复与 Git 代码恢复分别验收。
6. 长期记忆来源、事实验证、撤权后的访问拒绝。

当前代码搜索课程继续；进入会话/上下文阶段按本设计实现，不提前生成整套后端，也不删减已确定功能。
