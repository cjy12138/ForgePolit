# 第 1 课：实现最小 Agent 循环

## 目标

直接学习 Agent 核心，不安排 Python 语法、虚拟环境或 JSON 基础练习。实现一次模型请求工具、程序执行工具、模型读取结果并结束的闭环。预计 45–90 分钟。

本课用假模型固定响应，方便观察控制流；本阶段后续接真实模型 API。这只是教学中间态，不缩减最终双模式、插件化、权限与会话等功能。

## 核心流程

```text
用户输入 → 模型生成响应
              ├─ 最终回答 → 保存回答并返回
              └─ 工具调用 → 保存调用 → 执行工具
                              → 保存对应结果 → 再调用模型
```

模型只提出工具调用，程序实际执行。历史同时保存模型调用和工具结果，通过调用 ID 关联；不能只把工具结果塞进消息。

## 动手任务

在 exercises/lesson01.py 中实现三个部分：

1. FakeModel.generate(messages)：没有工具结果时返回 read_file 调用；收到结果后返回最终回答。通过消息判断进度，避免不同运行共享计数器导致串状态。
2. read_file(path)：只允许读取项目根目录的 README.md，以 UTF-8 返回文本。本课先固定可读文件，不开放任意路径或命令。
3. run_agent(user_input, model, tools, max_steps=5)：循环调用模型、保存响应、分派工具、保存结果，返回最终回答及完整轨迹。

教学响应协议示例：

```python
# 模型请求工具
{"type": "tool_call", "id": "call_1", "name": "read_file",
 "arguments": {"path": "README.md"}}

# 工具执行结果
{"role": "tool", "tool_call_id": "call_1", "content": "文件内容"}

# 模型最终回答
{"type": "final", "content": "这是一个插件化双模式编程 Agent 项目。"}
```

这些是内部教学协议，不是某一家 API 的原生格式；后续适配器负责转换。保存模型响应时标记 assistant 角色，并保留调用 ID、名称及参数。

## 验收

从项目根目录使用已配置的 Python 运行 python exercises/lesson01.py：

- 输入“读取 README.md，告诉我这个项目是什么”，可见用户消息→模型调用→工具结果→最终回答。
- 工具调用与结果的 ID 对应，最终回答进入完整历史。
- 换成请求未知工具的假模型，不会执行未注册动作，轨迹保留错误。
- 换成一直请求工具的假模型，最多发起 max_steps 次模型请求后停止并说明原因。
- 连续运行两个任务，消息与假模型行为不会互相污染。
