# Markdown 记忆实施方案

更新：2026-10-06。依据用户截图调整，采用职责划分，不宣称复刻当前 Claude Code 内部实现。本文替代学习计划中长期记忆使用 SQLite 的旧方案。

## 存储与召回

- 当前用户、项目、仓库范围下保存主题 Markdown，YAML 元数据包含名称、类型、描述及来源。四类为 user、feedback、project、reference；按主题命名，不固定为四个文件。
- MEMORY.md 是可重建的部分索引，每行一个链接及短描述，最多 200 行、25 KiB；主题 Markdown 文件数量不受这个上限限制，正文不常驻。
- 索引收录名单持久化在当前记忆范围的 `.memory-index.json`。重建只刷新已选主题的描述，不重新收录被移出的主题；未收录的文件仍由全目录 header 扫描、glob、grep 发现。
- 提取 Agent 和 AutoDream 均在候选中提交 `index_change: {add: [...], remove: [...]}`，输入包含当前收录名单、索引条目数与字节限制。索引选择不要求读取正文；修改或删除正文仍遵循原有来源与版本校验。`remove` 只移出索引，不能删除文件。
- 显式空 `index_change` 保持收录选择，新增正文可不收录。兼容旧候选省略该字段时，仅在索引容量允许时自动收录新增主题；更新已有主题不重新收录它。默认行为不判断语义优先级，重要条目由两个 Agent 选择。
- 首次读取旧目录时，以原有 MEMORY.md 中的合法主题链接迁移选择；没有旧索引时采用容量内的确定性初始名单。后续以持久名单为准。正文和索引状态发布前整批预检，普通文件操作异常时恢复涉及的旧文件；不宣称多文件写入能抵抗进程崩溃。
- extract 覆盖已有主题前，将被更新主题的原始 Markdown 字节、旧 MEMORY.md、旧 `.memory-index.json` 及本次 proposal.json 保存到当前范围的 `.extract-backups/<备份ID>/`。每次更新创建独立备份，纯新增不生成旧主题备份；备份失败不覆盖正式文件。AutoDream 继续使用 `.dream-backups/`。备份是旧记忆正文，`previous_sources` 仍只保存原始对话引用，两者不混用。
- `list_memory_versions(filename)` 列出 extract/AutoDream 的历史备份，`read_memory_version(filename, version_id, offset, limit)` 按需读旧 Markdown，支持合并删除的主题。版本 ID 只允许类型及备份 UUID，不接受任意路径；作用域由当前 MarkdownMemoryStore 绑定。新备份以 backup.json 标记 prepared/published 并校验文件哈希，未发布或损坏的备份不可读取；已有无标记备份兼容读取并标注 legacy_unknown，不宣称其发布已成功。
- 两个旧版本工具已注册到提取 Agent、AutoDream 及 CLI 主 Agent。主 Agent 的旧正文读取共用原有会话累计读取额度；独立记忆 Agent 使用自己的请求预算。历史正文不会自动注入或恢复，不算作已读取当前主题，不改变当前会话游标；旧规则不能覆盖明确的新规则。
- 主题读写、索引维护、read_memory 工具及请求前缀接口已写；索引与控制器的联动仍需离线验收。
- 默认采用 manifest selector：扫描当前范围全部合法主题文件的前 30 行，解析完整 frontmatter，产出文件名、路径、修改时间、description、type；异常 header 标记跳过。不依赖 MEMORY.md 是否列出全部主题。
- 新用户节点首次准备请求时调用独立选择模型，输入 description 一行清单、用户需求及最近 10 个工具名称，结构化选择 0～5 个文件。程序不做关键词相关性排名；选择模型目前沿用 DeepSeek，可通过 MEMORY_MODEL 单独配置。
- 仅选中后读取正文，自动召回每文件最多 200 行和 4 KiB（UTF-8 字节）；正文读取累计每会话 60 KiB。read_memory 补读也计入额度，glob/grep 保留供主 Agent 补查。片段返回 truncated 和正文字符 next_offset。
- 同一用户节点复用轮次开始时的正文快照，工具循环、压缩与进程恢复不重复选择或扣减快照额度；新用户节点重新选择。召回快照及累计字节存为会话旁的 .memory-recall.json，不写原始会话历史。不是对每次重复发送的 API 输入字节计费。
- 选择失败、候选清单超过输入预算或正文读取失败不阻断业务，本进程本轮不重复请求，保留主动搜索/读取能力。索引和正文都是参考资料，不能覆盖任务约束或权限。

## 三项职责与触发条件（用户最新确认）

1. **extractMemories**：模型最终回答且工具交互完整后触发 Fork 记忆 Agent。默认每个新的完整用户轮次处理一次，可配置每 N 轮；同一最终节点不重复执行。以当前分支快照为上下文，重点提取最近新增的完整交互；completed 不表示测试已通过。只新增/更新 user、feedback、project、reference 主题，程序核验原始来源与范围后写文件并更新索引。无可复用信息返回空列表。不持久化易过期的代码事实、一次性测试结果、密钥和临时许可。
2. **Session Memory**：当前分支的累计历史消息 Token 估算达到 10K 后首次触发，之后每增加 5K 更新一次。计数按新增历史增量，不能直接使用压缩后的请求长度或累加重复发送的 API 输入 Token。在完整工具交互边界创建快照，由 Fork Agent 生成/更新一个 session_notes.md，包含任务、限制、进度、涉及文件、错误、实际测试证据和后续事项。记录来源锚点，切换分支后核验适用性并重建；生成失败不推进成功更新水位。仅当前会话使用，辅助恢复和后续摘要，不能替代原始历史、权限或 Git 代码检查点，也不与同一摘要重复注入。
3. **AutoDream**：同一记忆范围距上次成功整理至少 24 小时、至少有 5 个不同会话产生新活动、并获得记忆写锁时触发。在 CLI 启动或轮次结束检查，无常驻定时服务；时间未到先退出，成本低。初次运行以范围状态建立时间基线。Fork Agent 读取现有记忆和限定范围的会话记录，合并、去重、精简、识别过期条目；不凭空增加事实。程序校验后提交，修改/删除前备份，不确定冲突留待用户处理。完成后更新整理时间与会话水位；失败不更新时间。

## Fork Agent 的简化实现

- 保留真正独立的记忆 Agent 循环：复制当前分支上下文快照，使用独立消息列表、模型适配实例、提示词、受限工具集和预算，不修改主 Agent 消息。
- 单个后台工作器串行处理记忆作业，结果由主流程核验/发布；不做多 Agent 调度平台或严格两轮工具模式。
- extractMemories/AutoDream 只能访问当前范围的记忆及授权来源，提交记忆变更；Session Memory 只能提交当前会话笔记。不注册命令执行、业务代码编辑、MCP 或再派生 Agent 的工具。受限工具接口不宣称是操作系统安全沙箱。
- 所有主题写入、整理和删除共享一个简单文件锁；不自实现 PID 超时回收协议。候选在发布时核验来源分支与文件版本，避免旧作业覆盖新结果。
- 索引 200 行/25 KiB 是程序硬限制，不依赖模型遵守，也不限制主题文件数。两个 Agent 可交换收录条目或不收录新主题；不为腾索引空间而删除事实、强行合并不相关主题。非法索引候选在写入正文前拒绝并提示。容量压力提前触发整理仍是后续接入项。
- 无关错误不得阻断业务；CLI 显示记忆作业进行中/失败状态，退出时按有限超时收尾。保留手动触发整理命令供演示和修复。

## 教学顺序和验收

索引上下文验收 → 自动召回与预算/去重 → Fork 记忆 Agent 与受限工具 → 提取/写入与来源核验 → Session Memory 的增量触发及分支绑定 → AutoDream 触发、写锁、备份和索引限额。

最终演示跨会话召回、无相关记忆不选择、重复正文不注入、分支来源不混入、错误不写入、整理可回退，以及正式授权阶段的撤权拒绝。只做功能验收，不引入强制对比实验。

Prompt cache 不等于零 Token 或免费请求；实际输入、输出、缓存及用量按供应商返回统计。
