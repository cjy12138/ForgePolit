# ForgePilot 学习与实施路线

更新：2026-09-26。此计划替代旧版以 Bug 修复与消融实验为主的路线。

## 已确定的设计

### 教学与范围约定（用户确认）

- 分阶段教学只调整实现顺序，不删减已经确定的功能。最小示例、假模型和单机串行版本是教学中间态，不是最终交付范围。
- 完整交付保留：Python Agent 核心；API 任务理解、澄清与路由；插件接口、注册与生命周期；模型适配、检索与工具执行；交互编程与隔离自动修复；树形会话与持久化；上下文压缩与长输出读回；Git 代码检查点与恢复；项目长期记忆；统一接入、身份认证、项目/仓库授权与审计；交互式 CLI 及任务进度、取消与中断处理。
- 标为后续阶段的上述功能仍是项目待办，不能在最小版本运行后宣称整个项目完成。每个模块分别记录未开始、教学简化版、完整实现、已验收状态。
- 若技术限制或工作量需要改变已确定范围，先说明影响并与用户讨论，不自行删除、降级或无限期搁置。
- Pi 的全部功能不自动成为项目范围。Skills、完整 Pi 插件兼容等未确定能力单独讨论，不能与已承诺功能混淆。
- 用户已说明跳过 Python 基础。下一次授课直接从 Agent 核心开始，必要语言知识随实现讲解；不再要求完成虚拟环境、JSON 等基础练习作为前置条件。

- 主体 Python，自实现 Agent 核心；借鉴 Pi，不直接嵌入 TypeScript 运行时。
- API 模型理解任务并输出结构化分类，不部署本地模型。用户指定模式优先；缺失信息先澄清。
- 上层理解与路由，下层插件化执行。自己实现小型接口、注册表与生命周期，不复刻完整插件框架。
- 交互编程与自动修复共用一个 Agent 循环。自动修复只借鉴 mini-swe-agent 的执行方式，不嵌套它的内核。
- 独立命令进程不继承上一次 Shell 的临时状态，但文件与任务历史持续存在。它不等于每轮清空工作区。
- 树形会话参考 Pi：不可变历史节点、父节点关联、当前分支叶子。代码检查点与对话分支分别管理。
- 支持预算驱动的上下文压缩、项目记忆、统一身份认证、项目和仓库授权。
- 不安排必做的 benchmark、消融或对比实验；保留必要的功能与故障验收，不声称未经验证的性能提升。

## 架构与职责

```text
统一接入 / 身份认证
  → 项目授权
  → API 任务理解 / 结构化校验 / 模式路由
  → 上下文构建（当前分支、项目规则、摘要、授权记忆）
  → Python 插件化执行层
      执行策略：交互编程 / 自动修复
      AgentLoop：模型 → 工具 → 反馈 → 模型
      ModelAdapter / Tool / ExecutionEnvironment
  → 事件与树形会话存储
  → 补丁、测试结果、人工评审
```

权限由程序和执行环境执行；模型只得到必要说明。工具执行、历史读取、产物下载、记忆召回都要检查范围。身份来自可信认证结果，不来自用户 JSON 或模型输出。

会话管理同时服务上层上下文构建与下层执行记录。完整轨迹独立保存，摘要不能覆盖原始历史。

### 补充架构：Harness、插件容器与 AgentLoop

根据用户补充的三张架构说明图细化职责；以此前明确选择为准：本地模型替换为 API 模型，Pi/Cordis 具体运行时替换为 Python 自实现，不将截图中的大型仓库规模视为本项目事实。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| API 任务理解 | 提取目标、建议模式、识别待澄清信息 | 授权、直接运行命令 |
| Harness | 校验分类结果；结合项目配置与权限构建上下文；选择执行策略及适配器；管理状态、预算、取消、审批和结果验收 | 代替模型逐步推理、实现每个插件的内部逻辑 |
| Python 插件容器 | 插件注册、依赖注入、装配、能力兼容检查、初始化和清理 | 模型推理、自行授予权限 |
| AgentLoop（参考 Pi） | 组织模型调用、工具请求和反馈，报告过程事件与结束结果 | 绕过 Harness 的执行约束、决定自己拥有哪些权限 |
| ModelAdapter | 将统一消息与工具协议映射到模型 API | 直接操作工作区 |
| Retriever | 代码搜索、上下文获取，按项目配置选择实现 | 未经授权跨项目搜索 |
| Tool / ExecutionEnvironment | 在受控环境中执行读取、编辑、命令和测试 | 绕过统一工具执行入口 |
| SessionStore / MemoryStore | 持续记录会话与运行事件；筛选、验证、保存及按权限召回项目经验 | 将全部历史或模型猜测自动转成可信知识 |

Harness 是执行支撑与管理层，不是第二套 Agent 循环。它生成运行策略与可信执行上下文，统一工具执行入口在每次操作前落实权限、预算、审批与取消约束。AgentLoop 只通过该入口执行工具。

任务进入流程：身份/权限检查 → 新任务 API 理解（需要时）→ Harness 校验与上下文组装 → 插件容器装配 → AgentLoop 执行 → 持续记录事件 → Harness 收集与校验结果。

查询任务状态、取消、提交审批结果走确定性接口，不调用分类模型，也不绕过认证。显式自动修复任务可按固定流程预处理，目标不清楚时仍应澄清。

Retriever 按项目配置选择本地文本检索或未来外部服务；先实现本地检索和可替换契约，接企业搜索服务需有实际接口与数据。300GB+ 是截图背景，不是当前数据规模、性能承诺或必做压测。

可替换性不等于运行中任意热切换。任务开始时解析并记录插件配置与版本；缺少能力或依赖时明确失败并清理已初始化资源。运行中切换引擎或环境须另有状态迁移协议，当前双模式无需该能力。

会话存储贯穿执行过程，保存消息、工具记录和进度。长期记忆从过程与结果中提取候选，确认来源、版本、验证状态与授权范围后写入；召回后再参与上下文组装。会话保存不代表进程自动恢复。

教学映射：插件阶段加入依赖装配及失败清理；路由/双模式阶段实现 Harness；权限阶段补齐执行审批与审计；会话与记忆阶段验证上述职责。所有此前承诺功能保留，不因为此分层而删减。

## 技术与范围

- Python、类型注解、Pydantic；先普通函数，后 Protocol/接口；需要并发和取消时才引入 asyncio。
- 先 CLI 与假模型，在最小 Agent 阶段接真实模型 API；当前已接入 DeepSeek。密钥通过后端环境变量或被 Git 忽略的 .env 提供，不写入仓库或对话。
- JSONL 追加保存会话事件，SQLite 管理任务、身份、项目与可重建索引；命令行为正式交互入口，支持进度、取消和恢复，不实现 Web 前端。
- Windows 开发先跑安全的教学文件操作；自动修复 Bash 环境使用 Linux 容器，不依赖宿主机拥有 Bash。
- Git worktree 隔离文件修改，不是安全沙箱；容器需要限制挂载、凭据、网络与资源。
- 第一版单机、单 worker、串行任务，自己维护可信插件；暂不做第三方不可信插件、分布式调度、通用多租户平台。
- 先做真实的用户认证与项目授权闭环；企业 OIDC/SSO 接入可作为后续扩展，不把演示账号当作真实员工目录集成。

## 教学方法与进度

用户最新明确的参考边界：mini-swe-agent 只参考独立进程执行的核心代码及相关执行结果、超时和清理细节，不以其整体结构、目录、装配工厂或配置体系指导本项目。整体继续采用已确定的 Python 自实现核心、Pi 核心设计与树形会话、Harness 和插件化方案；MiniCode 用于适合的具体模块实现，Claude Code 用于规则、记忆和上下文机制。参考源码不要求做对比实验。

参考入口与核对记录见 [MiniCode 学习映射](../references/minicode-reference.md) 和 [mini-swe-agent 参考记录](../references/mini-swe-agent-reference.md)。保持现有 forgepilot/ 包结构，不为模仿参考项目重做目录迁移。已经实现的 Protocol、依赖注入和注册校验作为本项目插件化基础保留，不将它们描述为用户要求照搬 mini 的结构。runtime 装配提案仅按本项目需求决定，不作为模仿 mini 的必做迁移。

所有既定功能保留，包括 Harness、插件化、双模式、树形会话、上下文压缩、Git 检查点、长期记忆与身份授权。每课说明参考来源、采用内容及本项目改动；未读源码不作已核实声明，实际复制或改编时核对许可证。

每课约 30–90 分钟，按验收推进，不按日历赶进度。下表课号是原路线的定位编号，新增细分课不受原课数限制；原先 60–100 小时仅为粗略估计，按实际学习与实现进度重估，不通过删功能适配时长。不安排 Python 基础课程。

每课顺序：讲清问题 → 小例子 → 用户写一个小模块 → 运行验收 → 助手审查与提示 → 用户解释设计。助手不提前生成整套后端。若已掌握某阶段，通过验收即可跳过对应基础讲解。

## 分阶段课程

| 阶段 | 课程与所需知识 | 实际产出 | 通过标准 |
| --- | --- | --- | --- |
| 1：最小 Agent（1–3课） | 消息、工具 schema、模型适配器、循环、终止条件 | 假模型驱动一次读文件并回答；随后接真实模型 API | 看见模型→工具→模型轨迹；未知工具被拒绝；达到步数上限能停止 |
| 2：API 任务理解（4–5课） | TaskRequest / TaskIntent、Pydantic 结构化校验、有限重试、规则优先级 | 新任务→API 分类→程序检查→选择模式 | 拒绝空输入与错误模式；请求不能指定可信身份或服务器路径；用户显式模式优先；模糊需求进入澄清；无效模型输出不会启动执行 |
| 3：插件执行层（6–8课） | Protocol、注册表、依赖注入、异常和生命周期 | 模型、工具、执行环境接口；受限读取/搜索/编辑；FakeEnvironment | 可替换实现而不改 AgentLoop；重名工具与非法参数拒绝；调用携带可信执行上下文 |
| 4：树形会话（9–11课） | JSONL 追加、重放、写入控制、父子关系、游标事件和调用 ID | 持久化、当前分支查询、分叉、历史恢复 | 重启后恢复；分支不串历史；完整调用与结果关联；禁止在未完成调用中任意分叉 |
| 5：上下文管理（12–14课） | Token 预算、完整交互分组、摘要、长输出外存 | 原始轨迹与模型上下文分离；阈值压缩；按需读回 | 长日志可找回；保留目标/约束/进度；摘要失败可控退出或降级；不会重复执行工具 |
| 6：双模式与隔离（15–18课） | subprocess、超时、进程清理、Docker、Git diff、验收状态 | 交互开发策略；独立修复任务环境；修改→测试→结果 | 一个真实教学 Bug 修复前失败、修复后通过；任务间文件隔离；超时/失败有结果；默认不推送 |
| 7：接入、身份与授权（19–22课） | FastAPI、认证、服务端权限、对象级访问控制、审计 | 登录、项目列表、任务创建查询取消、受控工具访问 | 用户 A 无法读取 B 的项目/会话/产物；客户端伪造身份无效；Shell 不能绕过文件范围 |
| 8：交互 CLI 与恢复（23–25课） | 进度展示、取消、中断对账、Git 检查点 | 交互 CLI；分支关联代码检查点 | 取消后停止新动作；恢复先预览；不盲目重跑状态未知的写操作 |
| 9：项目长期记忆（26–27课） | 会话摘要与长期记忆区别、来源/范围/版本、失效 | 项目约定、验证经验；候选→确认→入库→授权检索 | 经验有来源；猜测不当事实；失去仓库权限后不能通过记忆读取内容 |
| 10：交付（28课） | 文档、演示、设计取舍与限制 | 安装说明、架构图、演示脚本、真实简历描述 | 新环境可启动；演示双模式、分叉、压缩、拒绝越权；每条简历可定位实现 |

### 新增材料对应的细分课程与验收

本节补齐上表阶段 4、5、8、9 的交付范围；具体契约以 [会话、上下文与记忆设计](../architecture/session-context-design.md) 为准。短期任务记忆在阶段 4–5 实现，不等到长期记忆阶段才加入。

| 阶段 | 逐步实现顺序 | 必须通过的验收 |
| --- | --- | --- |
| 4A：会话落盘 | 定义事件与会话头 → 单写者追加 JSONL → 重放与可重建索引 → 工具开始/结束记录 | 重启恢复；识别不完整尾行；中间损坏明确报错；整轮失败不丢失已完成记录 |
| 4B：树与任务状态 | 父节点校验 → 当前叶子与游标事件 → 分叉/切换 → 结构化任务检查点 | A-B-C-D 与 A-B-E 不串历史；游标可恢复；调用与结果配对；保存目标、约束、验收条件、进度、事实/假设和待完成动作 |
| 5A：上下文构建 | 当前分支路径 → ContextBuilder → 完整请求预算与供应商 usage 归一化 | 每次模型请求前检查；包括系统规则、工具 schema、任务状态和输出预留；分支/模型/压缩变化使旧 usage 边界失效 |
| 5B：长输出管理 | 完整输出先保存 → 原文/片段/产物预览分层 → 按范围读回 | 大输出可找回；不先截断再保存；保留错误定位信息；读取经过项目权限检查（阶段 7 完成真实身份联调） |
| 5C：摘要与短期记忆 | ContextPolicy → Compactor → 追加压缩节点 → 摘要+近期原文+结构化任务状态 | 连续压缩与旧分支均正确；不切断工具交互组；保留目标/约束/证据；失败不发布半成品；80%/16% 仅为可配置初始策略 |
| 5D：溢出与恢复契约 | 保存检查点 → 压缩/重建 → 最多重试一次失败的模型请求 | 不重放工具；用假执行后端验证待完成作业仍关联原 job_id；状态未知标记中断；旧测试不能证明新版本代码通过 |
| 8：接入真实恢复 | 绑定实际执行后端并对账 → 恢复任务与审批状态 → 独立 Git 检查点与代码恢复 | 恢复前重新授权；不盲目重跑写操作；会话切换不自动回退代码；保护工作区修改及必要未跟踪文件；不承诺恢复原进程 |
| 9A：长期记忆写入 | 四类候选 → 来源/范围核验 → Markdown 主题文件与索引 | 保存 user/feedback/project/reference 信息；不存易过期代码事实、密钥或临时权限 |
| 9B：召回与维护 | 每条新用户消息选择 0～5 个主题 → 范围/去重/预算过滤 → 正文注入；手动整理 | 跨会话可复用；撤权后不可召回；整理预览、确认和备份；工作笔记复用现有摘要 |

依赖顺序：工具与执行记录 → 会话树与任务状态 → 输出存储与上下文压缩 → 真实执行/授权联调 → Git 恢复 → 长期记忆。前期用固定本地测试身份和假作业后端验证契约，后期必须替换为可信认证结果和真实执行状态；教学替身不算完整验收。

交付阶段追加演示：长日志读回、压缩后继续原任务、跨会话召回有来源的记忆、旧记忆失效与撤权拒绝。只做功能与故障验证，不新增 benchmark 或消融实验。

## 重要实现约定

### 工具与插件

当前教学实现 ToolContext 仅携带 workspace，尚未实现身份授权。进入权限阶段需由可信入口补齐 user_id、project_id 和允许能力；固定身份只用于本地测试，生产入口必须由服务端认证和授权生成，不能接受模型伪造。

工具声明名称、参数 schema 与所需能力；核心校验再执行。插件接口随第二个真实实现出现时抽象，不为未来插件预造复杂系统。

### API 分类与模型调用

任务理解和执行共用模型适配层，但拥有不同提示与输出契约。API 分类只用于新任务或明确转向，不在每个工具步骤额外调用。TaskIntent 只描述建议模式、目标与澄清问题，不决定用户权限。模型故障、格式故障与工具故障分别处理，有限重试，不自动重试所有写操作。

### 树形历史与压缩

采用用户补充的追加式会话树与压缩节点设计，详见 [会话、上下文与记忆补充](../architecture/session-context-design.md)。会话日志改为 JSONL，SQLite 保留任务与索引职责。截图的 Pi 实现细节待源码核对，固定 Token 数值不直接照搬；保留单轮请求前预算检查。

最小节点包含 id、session_id、parent_id、kind、payload、created_at；会话记录 active_leaf_id。工具调用/结果记录关联 ID，分叉默认仅发生在已完成交互边界。摘要记录覆盖的祖先节点范围，只能用于对应分支，不使用全局最新摘要代替分支摘要。

### 自动修复与状态

建议状态 queued→running→awaiting_review→completed，另有 needs_input、failed、cancelled、interrupted、rejected。探索/修改/测试可先用阶段事件记录，不急于创建庞大状态机。测试通过是证据，模型声称完成不是成功证明；结果中绑定代码状态和测试命令。

### 恢复与记忆

恢复会话不等于恢复代码或进程。代码检查点记录基准 commit、diff 和必要未跟踪文件；第一版不恢复后台进程。恢复前检查实际工作区，状态不明的副作用交给人工处理。

项目记忆采用 Markdown 主题文件与 MEMORY.md 索引，独立模型选择相关主题；不需要向量数据库。具体以 [Markdown 记忆方案](markdown-memory-plan.md) 为准。仓库撤权同时限制历史摘要、记忆和产物访问。
