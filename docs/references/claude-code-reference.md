## 官方行为与本项目选择

| 官方文档明确描述 | ForgePilot 采用方式 |
| --- | --- |
| CLAUDE.md 是人为维护的持久指令；auto memory 是模型积累的笔记；两者都是上下文，不是强制配置 | 分开 RuleLoader 与 MemoryStore；权限始终由 Harness/工具/环境落实。记忆沿用候选、验证、启用流程，不因模型写入就可信 |
| 上层目录指令按顺序拼接；子目录指令按需加载；路径规则匹配相关文件后加载 | 只在授权项目根内发现规则；项目通用规则启动加载，目录规则按访问路径加载。在读取/编辑相应文件后、下一次模型决策前装配，防止只写不读漏掉规则；这是本项目策略，不声称与 Claude 完全相同 |
| 指令导入在启动时展开；拆成多个导入文件不等于节省上下文 | 采用有预算的通用规则与按需目录规则；初版不提供任意外部路径导入。未来支持导入时须校验范围、环、深度和总大小 |
| MEMORY.md 是精简索引，详细主题文件按需读取；当前文档启动加载上限为前 200 行或 25KB，取先达到者 | 借鉴“索引+详情”，不照搬数值或文件布局。SQLite 为长期记忆事实来源，生成授权范围内的简短索引，详情经 memory_id 读取并再次授权；索引也受 Token 预算限制 |
| auto memory 可开关，用户可浏览、编辑和删除 | 提供候选生成开关、来源查看、修正、停用/删除入口。删除内容不得由旧索引或缓存继续召回；审计记录不作为模型可用记忆 |
| 接近窗口上限先清理旧工具输出，再按需总结；支持 /compact 和重点提示 | 保留既定“完整输出先外存→精简视图→历史摘要”；自动和手动压缩走同一 Compactor，用户可指定重点，不能删掉强制保留的任务约束/证据 |
| 根项目指令在压缩后重新注入；目录指令及路径规则在相关读取时重新加载 | ContextBuilder 从独立规则来源重建，不依赖摘要保存规则；重建时保留当前任务仍适用的目录规则，去重并记录来源/内容版本 |
| /context 可查看占用；/memory 可管理记忆 | CLI 先提供上下文构成、预算、规则和记忆来源报告，阶段 8–9 接入界面。估算值与供应商实际 usage 分开标注 |
| 超大输入持续引起压缩时停止并报错；文件检查点不是 Git 的替代品 | 保留本项目最多一次超限模型请求重试；会话恢复、Git 恢复、执行状态对账继续分别实现 |

## 不直接照搬的内容

- 不把目录路径作为用户/项目身份，不让同仓库不同员工默认共享私人记忆。以可信 project_id、owner_id、visibility 决定可见性，worktree 只是代码位置。
- 不依赖“后加载的自然语言自动覆盖前面的规则”。标记作用域和来源；明确冲突呈现给用户，强制策略由程序处理。
- 不把修复案例、失败经验等四类记忆归因于 Claude Code：它们是 ForgePilot 已确定的记忆分类。
- 不因本次参考新增必做多 Agent、Skills 兼容、MCP 或 Claude Code 运行时集成。
- 不声称已知 Claude 的内部摘要提示词、精确触发算法或向量检索实现。

## 课程与验收映射

1. 阶段 5A：规则加载与上下文来源报告；验收无关目录规则不加载、跨目录修改加载适用规则、越权规则不可读取、冲突可定位。
2. 阶段 5C：手动/自动压缩共用流程；验收压缩后项目规则仍在、目录规则正确、无重复注入、原始证据可追溯。
3. 阶段 8：界面展示上下文组成和手动压缩入口，复用后端接口。
4. 阶段 9：授权索引与按需详情、候选开关、查看/修正/停用/删除；验收索引不泄露其他项目或私人记忆，停用/删除后不再召回。

这些是既定会话、上下文和记忆功能的具体细化；当前工具开发继续，后端仍由用户逐课实现。
